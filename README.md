# Анализ FTIR-спектров и компонентов Amide I

Программа `analyze_amide.py` обрабатывает реальные спектры слюны, оценивает относительные площади компонентов полосы Amide I и сравнивает экспериментальные группы на уровне отдельных животных. Четыре основные категории — Random coil, α-helix, β-sheet и β-turn; неоднозначные компоненты сохраняются как Unassigned. Программа не принуждает модель содержать все четыре категории и не заменяет неудачные результаты нулями.

Ранее созданный `ir_region_analysis.py` сохранён отдельно. Он сравнивает сигнал в девяти заданных ИК-областях и создаёт таблицу региональных сравнений. Он не выполняет разложение Amide I и не заменяет новый анализ вторичной структуры.

## Обновление 1.2.0 и проверка на реальных данных

Для диагностики предоставлены исходный реальный спектр и затем полный Excel-отчёт серии из 26 спектров, содержащий исходные данные. Число допущенных животных определяется повторным расчётом с текущей моделью и конфигурацией; результаты прежней версии нельзя переименовать в новые без пересчёта. Проверка на синтетических данных показывает работоспособность алгоритма и экспорта, но не подтверждает применимость модели к реальной слюне. Не выдавайте синтетические таблицы и графики за результаты эксперимента.

В прежней реализации центр ограничивался узким окном вокруг минимума второй производной. Для перекрывающихся полос такой минимум может быть смещён относительно центра компонента; попадание в искусственную границу приводило к отклонению переподгонок. В версии 1.1.0 центры свободно подбираются внутри всей полосы с сохранением порядка и минимального расстояния. Физически недопустимый результат больше не может выиграть у допустимого только за счёт меньшей ошибки. Неудачные bootstrap-переподгонки повторяются с дополнительными начальными приближениями; причины окончательных неудач сохраняются отдельно. Пороги качества сохранены, включая SD долей ≤8 процентных пунктов и долю успешных переподгонок ≥80%. Улучшение численной процедуры не гарантирует устойчивого разделения всех перекрывающихся компонентов. Повторяющиеся старты поиска сокращены; полный расчёт с повторными bootstrap-попытками может занимать больше времени.

В версии 1.2.0 линейный остаточный фон оценивается одновременно с гауссовыми компонентами. Простое вычитание прямой по краям полосы могло удалить хвосты широких компонентов и сместить их площади. Теперь начальная коррекция используется для производной и поиска стартовых центров, а при каждой подгонке и bootstrap-переподгонке фон уточняется совместно с пиками. AICc/BIC учитывают оба коэффициента уточнения фона. Пороговые значения качества не снижены. Чувствительность долей проверяется при единой классификации компонентов, учитывающей bootstrap-интервалы и альтернативные обработки; дополнительно проверяется изменение площадей отдельных компонентов.

Пользователь подтвердил спектральное разрешение своего прибора: **4 см⁻¹**. Образцы измерены в виде высушенной плёнки слюны. В поставляемом `analysis_config.json` заданы `spectral_resolution_cm1: 4.0` и `resolution_confirmed: true`. Шаг экспорта около 1,93 см⁻¹ остаётся отдельной характеристикой сетки. Подтверждение разрешения снимает только соответствующее условие допуска; неустойчивые разложения по-прежнему исключаются. Для другого прибора укажите его фактическое разрешение. Универсальные настройки `default_config()` и команда `--write-default-config` сохраняют `resolution_confirmed: false`, пока значение не подтверждено для конкретного измерения.

В отчёте отдельно указаны `numerical_fit_reliable` (численная устойчивость при заданных настройках), `quantitative_accepted` (допуск к количественной статистике), `fit_rejection_codes` (причины отклонения модели) и `protocol_blockers` (неподтверждённые условия измерения). Диагностические площади сохраняются на листе `Diagnostic_Structure`, в том числе при неизвестном разрешении; они не поступают в групповые тесты. Сообщение о нуле допущенных животных само по себе не означает ни ошибки чтения, ни отсутствия сохранённого Excel.

## Установка и запуск

Нужен Python 3.11 или новее. Обязательные библиотеки перечислены в `requirements.txt`; Seaborn не требуется.

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей команды:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Запуск с путями к данным и метаданным:

```bash
python analyze_amide.py \
  --input /path/to/spectra \
  --metadata /path/to/metadata.xlsx \
  --config analysis_config.json \
  --output /path/to/amide_results
```

В Windows ту же команду можно записать в одну строку. `--metadata`, `--config` и `--output` необязательны; при наличии `metadata.xlsx` во входной папке программа использует её автоматически. Без `--output` создаётся папка `Amide_results_<время>` рядом с входной папкой. Без `--input` открывается диалог выбора папки, если доступна графическая среда. На сервере или в облачной среде передавайте `--input` явно. Графики сохраняются без открытия окон.

После обновления распакуйте новую программу в отдельную папку и выполните установку библиотек. Для повторного анализа используйте прежние исходные данные и метаданные, но новую выходную папку. Старые результаты не смешивайте с новыми. Сохранённая конфигурация прежней версии совместима: отсутствующий `fitting.bootstrap_retry_multistarts` автоматически получает значение 3. Если вы явно передаёте старый JSON через `--config`, проверьте в нём подтверждение разрешения: для этого прибора установите 4.0 и `true`. Без `--config` используется новый `analysis_config.json` рядом с программой. Консоль показывает этапы анализа каждого файла и время без сохранения графиков (`analysis_seconds`), затем отдельно сообщает число прочитанных спектров, численно устойчивых разложений и животных, допущенных к статистике, а также полный путь к Excel.

Чтобы сохранить универсальную конфигурацию с неподтверждённым разрешением для нового проекта:

```bash
python analyze_amide.py --write-default-config my_analysis_config.json
```

Каждая облачная задача уже выполняется в изолированной среде. Используйте существующий checkout; отдельный Git worktree для установки или запуска не нужен.

## Входные данные и животные

Поддерживаются `.xlsx`, `.xls` и `.csv`. Первые два заполненных столбца содержат волновое число в см⁻¹ и Absorbance. Допускается один ряд заголовков и любое направление оси. В Excel должен быть не более одного непустого листа со спектром. Пустые строки и недостающие значения удаляются с предупреждением, одинаковые волновые числа усредняются. Некорректные текстовые значения и бесконечности вызывают ошибку данного файла, остальные файлы продолжают обрабатываться.

По умолчанию каждый файл считается отдельным животным, а первая подпапка определяет группу. Число групп и животных не зашито в код:

```text
spectra/
├── Control/
│   ├── mouse_01.xlsx
│   └── mouse_02.csv
├── SHAM/
├── Infection/
├── Cancer_2-3mm/
├── Cancer_4-6mm/
└── Cancer_7mm_plus/
```

Файлы непосредственно во входной папке относятся к группе `Ungrouped`. Для содержательного сравнения групп укажите подпапки или метаданные. Программа не угадывает технические повторы по похожим именам файлов.

Если есть повторы одной мыши, **обязательна таблица метаданных**. Колонка `file` содержит путь относительно входной папки; `animal_id` — идентификатор животного; `group` — группу. `technical_repeat` необязательна:

| file | animal_id | group | technical_repeat |
|---|---|---|---|
| Control/mouse01_repeat1.xlsx | mouse01 | Control | 1 |
| Control/mouse01_repeat2.xlsx | mouse01 | Control | 2 |
| Cancer_2-3mm/mouse02.xlsx | mouse02 | Cancer_2-3mm | 1 |

Один идентификатор животного не может принадлежать разным группам. Таблица должна однозначно соответствовать обнаруженным спектрам: отсутствующие строки, дубликаты и лишние пути выявляются до анализа. Метаданные и временные файлы Excel не анализируются как спектры. Сохраняйте выходные данные отдельно от исходных.

Каждый повтор сначала проходит полный анализ. Принятые проценты усредняются внутри животного. Если хотя бы один повтор не прошёл контроль качества либо расхождение процентов превышает `replicates.max_repeat_delta_pct`, животное исключается из статистики с указанием причины. В таблицах сохраняется число повторов. Число спектров не подменяет число мышей.

## Алгоритм и параметры

Подробное описание и текст для раздела статьи находятся в [METHODS_RU.md](METHODS_RU.md). Основные этапы:

1. Проверка данных, очистка, сортировка и выделение 1600–1700 см⁻¹. Границы меняются через `amide_bounds`. На границах допустима интерполяция внутри измеренного диапазона; экстраполяция запрещена.
2. Начальная коррекция базовой линии: линейная по краям полосы по умолчанию либо асимметричный метод наименьших квадратов (`baseline.method: "als"`). При разложении остаточный линейный фон уточняется одновременно с компонентами. Сохраняются исходная и уточнённая линии фона и соответствующие скорректированные сигналы.
3. Сглаживание и вторая производная Савицкого — Голея. Окна задаются в см⁻¹ и преобразуются в нечётное число точек. При неравномерной оси программа сообщает о пересчёте на равномерную сетку. Производные для нескольких окон рассчитываются независимо из скорректированного сигнала.
4. Поиск воспроизводимых минимумов второй производной. Минимумы дают начальные оценки пиков; они сами по себе не доказывают наличие отдельной структуры.
5. Ограниченная аппроксимация суммой положительных гауссовых компонентов и остаточного линейного фона. Для каждого набора параметров пиков два коэффициента фона оцениваются линейным методом наименьших квадратов. Все непустые подмножества устойчивых кандидатов дают начальные приближения; при максимуме 6 кандидатов их не более 63. После свободного подбора центров разные подмножества одного размера являются стартами одной модели с K компонентами. Сравниваются лучшие допустимые модели разных K по AICc/BIC с числом параметров 3K + 3, включая фон и остаточную дисперсию; неподходящие решения остаются в диагностике, но не могут быть выбраны. Центры упорядочены внутри всей полосы и разделены не менее чем на максимум из заданного минимального расстояния, разрешения и двух исходных шагов сетки. Фиксированного обязательного количества пиков нет. Аппроксимация использует данные до сглаживания; площади рассчитываются только по гауссовым компонентам.
6. Проверка уровня сигнала/шума, остатков, параметров у физических границ, определимости и устойчивости модели. По умолчанию выполняется 30 bootstrap-переподгонок с циркулярными блоками остатков длиной 3 точки. Если первый подбор не сошёлся либо физически недопустим, для исходного и конкурирующих K предусмотрены повторные старты. Неудача конкурента даёт неопределённое сравнение. Bootstrap условен относительно обнаруженных кандидатов, доступных K и выбранных исходных решений; весь поиск кандидатов заново не выполняется, поэтому интервалы не учитывают полностью неопределённость поиска/выбора модели. Проверяется также чувствительность к обработке. Высокий R² отдельно не делает модель достоверной.
7. Классификация устойчивых компонентов, расчёт площадей именно внутри анализируемой полосы и агрегация технических повторов. Надёжность классификации учитывается отдельно от общей пригодности аппроксимации.
8. Описательная статистика, межгрупповые сравнения и коррекция Бенджамини — Хохберга (BH). Статистическая единица — животное.

Некоторые важные настройки:

| Параметр | Назначение |
|---|---|
| `spectral_resolution_cm1`, `resolution_confirmed` | Фактическое разрешение прибора и подтверждение его источника |
| `baseline.method` | `linear` или `als`; выбор должен соответствовать фону исходных данных |
| `normalization` | `none` по умолчанию, дополнительные варианты — `area` и `l2` |
| `smoothing.window_cm1`, `derivative_windows_cm1` | Основное окно и окна проверки второй производной |
| `peaks.min_fwhm_cm1`, `max_fwhm_cm1` | Физически допустимые ширины с учётом разрешения |
| `peaks.max_components` | Верхний предел исследуемых моделей, не обязательное число пиков |
| `fitting.criterion` | `aicc` или `bic` |
| `fitting.bootstrap_iterations` | Число повторных аппроксимаций; 30 по умолчанию является практическим диагностическим минимумом, а не доказательством точности |
| `fitting.bootstrap_block_length` | Длина циркулярного блока остатков в точках; по умолчанию 3, значение 1 явно включает независимое пересэмплирование |
| `fitting.bootstrap_retry_multistarts` | Бюджет начальных приближений при повторе неудачной bootstrap-переподгонки; по умолчанию 3 дополнительных старта после первой неудачи; значение 1 отключает повтор |
| `assignment_ranges` | Настраиваемые диапазоны классификации компонентов |
| `statistics.method` | Заранее выбранный `mannwhitney` или `welch` |
| `statistics.bootstrap_iterations` | Повторы для интервалов величины эффекта |
| `plots.control_group` | Название группы с незакрашенными столбцами |
| `plots.merge_beta_turn` | Явное объединение β-sheet + β-turn только для дополнительного представления |
| `dataset_label` | Видимая подпись набора данных на всех рисунках; синтетический пример явно маркирован |
| `seed` | Воспроизводимость многократного подбора, bootstrap и статистических процедур |

Не выбирайте параметры постфактум по наиболее значимому межгрупповому результату. Любую замену исходных настроек зафиксируйте до окончательного анализа и проверьте на всех образцах одинаково. Длину bootstrap-блока следует соотнести со структурой остатков и проверить чувствительность к её выбору; короткие блоки не устраняют произвольную корреляцию или неоднородный шум. Для окончательных публикационных интервалов увеличьте число переподгонок, например до 500 и более, и проверьте сходимость. Сохранённая конфигурация `processing_config.json` и версии программ экспортируются вместе с результатами. Выходная папка должна быть новой либо пустой: существующие результаты не перезаписываются.

## Площади и ограничения интерпретации

Для принятой модели площадь каждого гауссова компонента интегрируется от нижней до верхней границы Amide I. Его доля равна `100 × площадь / сумма площадей всех включённых компонентов`. Категории Random coil, α-helix, β-sheet, β-turn и Unassigned в сумме дают 100%. Высокочастотный компонент 1680–1695 см⁻¹ относится к β-sheet только при достаточном обосновании его выделения и классификации. Компонент с неоднозначным положением остаётся Unassigned.

Отсутствие принятого компонента в категории может дать настоящую модельную долю 0%, но не означает доказанного отсутствия соответствующей структуры в слюне. При неудачной модели все принятые доли отсутствуют (`NaN`/пустые ячейки), а не равны нулю. Диагностические параметры и доли сохраняются отдельно, если удалось получить разложение, и не используются как подтверждённые результаты. Назначение учитывает общий интервал, охватывающий bootstrap-интервал центра основной модели и центры допустимых альтернатив с тем же числом компонентов, с защитным отступом. Если он пересекает границы назначения, компонент относится к Unassigned. Эта классификация одинакова для итоговых долей, успешных bootstrap-повторов и оценки чувствительности: случайное пересечение границы не создаёт искусственный скачок площади между категориями. Изменение долей отдельных компонентов проверяется дополнительно; неоднозначное назначение не скрывает их физическую неустойчивость.

Отношение α-helix/β-sheet и его логарифм рассчитываются только при математически допустимых значениях; логарифмические отношения требуют строго положительных числителя и знаменателя. Псевдосчётчики для скрытой замены нулей не добавляются. Проценты являются композиционными данными: увеличение одной доли меняет остальные даже при неизменной абсолютной площади. Отдельные тесты компонентов следует интерпретировать вместе с этим ограничением.

Слюна содержит смесь белков и других веществ. Вода и её изгибная полоса могут перекрываться с Amide I; на результат влияют высушивание, подготовка образца, фон, остаточная вода, белковый состав и межмолекулярные взаимодействия. Программа не отделяет вклад конкретного белка и не доказывает его конформационное изменение или развитие опухоли по одному показателю. Диапазоны классификации ориентировочны и требуют проверки применительно к материалу и литературе.

## Статистика и рисунки

Для принятых животных сохраняются n, среднее, SD, медиана, квартили/IQR и доступные доверительные интервалы. Метод задаётся заранее в конфигурации: Манн — Уитни либо Уэлч для двух групп; соответствующий общий тест — для нескольких групп. Все запланированные допустимые попарные p-значения вычисляются независимо от результата общего теста и входят в общую BH-коррекцию. При включённом `posthoc_only_if_omnibus_significant` интерпретация попарных результатов и скобки разрешены только при значимом **скорректированном** общем q; иначе точные попарные p/q сохраняются для проверки со статусом `gated`. Так число гипотез до коррекции не отбирается по исходным p. Нормальность не объявляется доказанной по незначимому тесту Шапиро — Уилка на малой выборке.

В таблицах указаны исходное `p_value`, скорректированное `q_value`, величина эффекта, её интервал и причина невозможности расчёта, если она есть. Положительный эффект в двухгрупповом сравнении означает более высокие значения `group2` относительно `group1`. BH применяется к общей семье реально проверенных гипотез этого запуска; дополнительные показатели и сравнения увеличивают её размер. Выводы по зависимым композиционным показателям требуют осторожности. При недостаточном n или вырожденных данных программа сообщает ограничение, а не выдаёт фиктивный интервал.

Основной рисунок показывает четыре категории отдельно: среднее ±SD, индивидуальные точки мышей, незакрашенный контроль и цветные экспериментальные группы. При `plots.merge_beta_turn: true` дополнительная объединённая категория называется **β-associated structures (β-sheet + β-turn)**; её нельзя подписывать как β-sheet. Значимые скобки основываются на скорректированных p-значениях; точные значения сохраняются в таблице. Отсутствие скобки не доказывает эквивалентность групп.

Для каждого спектра создаются полный исходный спектр, область до/после коррекции, вторая производная, компоненты/суммарная аппроксимация и остатки. На рисунке фона показаны начальная и уточнённая линии; на рисунке разложения наблюдаемый сигнал и сумма компонентов приведены относительно уточнённого фона. В папке `figures` это файлы `spectrum_0001_full_spectrum`, `spectrum_0001_baseline`, `spectrum_0001_second_derivative` и `spectrum_0001_decomposition` для первого спектра и аналогичные файлы для последующих. Межгрупповой рисунок сохраняется как `Secondary_Structure_Groups`, индивидуальные значения — `Secondary_Structure_Distributions`. Каждый имеет расширения `.png` (по умолчанию 300 dpi), `.pdf` и `.svg`. Ненадёжные аппроксимации явно помечены.

## Экспорт

Основной файл — `Amide_I_Results.xlsx`:

| Лист | Содержимое |
|---|---|
| `Metadata` | Файлы, животные, группы и повторы |
| `Raw_Spectra` | Исходные строки полного диапазона для проверки входных данных |
| `Processed_Spectra` | Область Amide I, начальный фон/коррекция, сглаживание и уточнённые `baseline_adjustment`, `refined_baseline`, `corrected_refined`, `gaussian_fit` |
| `Second_Derivative` | Вторая производная для используемых окон |
| `Peak_Parameters` | Параметры компонентов, площади и классификация |
| `Secondary_Structure` | Принятые доли и статус каждого животного |
| `Group_Statistics` | Описательная статистика |
| `Statistical_Tests` | Сравнения, p/q, эффекты и ограничения |
| `Fit_Quality` | Метрики качества, статусы и предупреждения |
| `Diagnostic_Structure` | Диагностические доли отдельных спектров, численная устойчивость и отдельный допуск к статистике |
| `Bootstrap_Diagnostics` | Результаты и причины неудач каждой bootstrap-итерации, повторы подбора и доступность сравнения K |
| `Processing_Settings` | Настройки, версии ПО и сведения о запуске |

Для каждого основного листа сохраняется одноимённый CSV. Дополнительные таблицы `Spectrum_Results.csv`, `Animal_Diagnostics.csv`, `Derivative_Candidates.csv`, `Model_Comparison.csv` и `Sensitivity.csv` содержат результаты отдельных спектров, причины исключения животных, кандидатов производной, сравнение моделей и чувствительность. `Unreliable_Spectra.csv` содержит отдельный перечень проблемных спектров. Ошибка одного спектра отражается в отчёте и не прерывает обработку остальных. Предел числа строк Excel контролируется без молчаливого усечения.

## Воспроизводимый синтетический пример

```bash
python examples/make_synthetic_data.py --output examples/generated_synthetic
python analyze_amide.py \
  --input examples/generated_synthetic/spectra \
  --metadata examples/generated_synthetic/metadata.xlsx \
  --config examples/generated_synthetic/synthetic_config.json \
  --output examples/synthetic_results
```

Если `examples/generated_synthetic` уже содержит предоставленный пример, пропустите генерацию и используйте существующие файлы либо задайте новую папку. Если папка результатов уже содержит предыдущий запуск, выберите новое значение `--output`.

Генератор создаёт **исключительно синтетические** данные: 8 условных животных в двух группах, 9 спектров, один набор из двух технических повторов. Имена животных начинаются с `SYNTHETIC_`. Конфигурация задаёт подпись `SYNTHETIC VALIDATION — NOT EXPERIMENTAL DATA` на рисунках. Полный диапазон около 450–4000 см⁻¹, шаг 1,93 см⁻¹; известные генерирующие компоненты имеют центры около 1630, 1655 и 1674 см⁻¹, FWHM 12, 10 и 12 см⁻¹, линейный фон и заданный шум. Здесь нет генерирующего Random coil, поэтому программа не должна принуждать модель к четвёртому пику.

`truth.json` содержит центры, амплитуды, ширины и точные площади внутри 1600–1700 см⁻¹ для каждого файла. `synthetic_config.json` подтверждает разрешение только в рамках математического примера. Не переносите это подтверждение в конфигурацию реального прибора. Одни и те же `--seed` и версии библиотек воспроизводят пример; генератор не перезаписывает непустую папку. Успешное восстановление простого гауссова примера не гарантирует идентифицируемость компонентов реального спектра.

Проверка версии **1.2.0** воспроизводится отдельной командой:

```bash
python examples/validate_overlap.py --output overlap_validation
```

В [сохранённом отчёте](examples/overlap_validation_summary.json) прошли все девять синтетических случаев: разделённые и умеренно перекрывающиеся компоненты, одиночный пик с шумом, один и два широких пика с хвостами на краях полосы, широкое неоднозначное перекрытие, граница назначения, чистый шум и неизвестное разрешение. Для смеси трёх умеренно перекрывающихся пиков максимальная ошибка центров составила **0,160 см⁻¹**, относительных площадей — **0,962 процентного пункта**. В примере двух широких пиков ошибка площадей не превысила **0,006 процентного пункта**. Широкое неоднозначное перекрытие четырёх компонентов остаётся отклонённым даже при R² > 0,999. Эти результаты относятся к указанным математическим примерам и не подтверждают точность анализа реальной слюны.

Архив синтетических результатов версии 1.0.0 не включён в ZIP программы. Для текущей версии используйте приведённые генератор и проверку.

Проверка модулей и ранее созданной региональной статистики:

```bash
python -m unittest discover -s tests -v
python -m unittest test_ir_region_analysis -v
```

## Перед анализом реальной серии

Проверьте протокол измерения и фактическое разрешение; подготовьте исходные Absorbance и правильные метаданные повторов. Осмотрите фон и воду, сопоставьте пригодность линейной/ALS коррекции с подготовкой образцов, обоснуйте диапазоны классификации и статистический метод заранее. На реальном тестовом спектре проверьте остатки, ширины, число компонентов и устойчивость при разных окнах. Если разложение неустойчиво, результатом является `Unreliable fit`; программное увеличение числа пиков не исправляет отсутствие спектральной информации.
